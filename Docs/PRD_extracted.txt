1. EXECUTIVE SUMMARY & OBJECTIVES
BookmarkAI Hub adalah sistem manajemen ide dan referensi dari media sosial (Instagram, TikTok, X, YouTube) yang terintegrasi penuh secara otomatis. Sistem ini menyelesaikan masalah information overload dan hilangnya konteks saat menyimpan postingan media sosial, tanpa bergantung pada langganan berbayar ($0 Cost Commitment).
Karena mayoritas konten yang disimpan user berasal dari Reels Instagram — format yang konteksnya sering tersimpan di narasi audio, bukan caption — kemampuan transkripsi audio dianggap sebagai fitur inti (core), bukan fitur tambahan, dan tetap masuk dalam scope v1.

Tujuan Utama Sistem:
Capture Cepat via Mobile: Input link & pesan opsional langsung dari aplikasi Telegram melalui fitur Share.
Automated AI Enrichment: Ekstraksi metadata, pembentukan ringkasan otomatis, serta penentuan kategori/tag hibrida (AI Auto-tagging + Manual Override).
Speech-to-Text Gratis (Core v1): Transkripsi audio postingan video (TikTok/Reels/Shorts), diekstrak via worker eksternal menggunakan yt-dlp, ditranskripsi menggunakan Groq Whisper API ($0 tier).
Advance Management Dashboard: Dashboard web berbasis Next.js untuk filter, pencarian teks, pencarian makna (semantic search), dan pengeditan data secara terpusat.
2. SYSTEM ARCHITECTURE & TECH STACK ($0 COST ASSURANCE)

3. USER WORKFLOW & FEATURES SPECIFICATION
3.1. Flow 1: Capture & Enrichment via Telegram Bot (Revisi: Two-Phase)
Flow ini direvisi menjadi dua fase — sinkron (cepat) dan asinkron (audio processing) — agar user tidak menunggu lama di chat sementara tetap mendapatkan hasil analisis lengkap termasuk transkrip audio.

Fase A — Sinkron (Instan)
Share Link + Optional Note: User mengirimkan link Reels/TikTok/postingan medsos ke Telegram Bot, dengan pesan manual opsional (misal: https://instagram.com/reel/xyz pelajari arsitektur ini).
Metadata Extraction: Vercel Webhook langsung mengekstrak OpenGraph metadata (judul, deskripsi publik, thumbnail).
Bot membalas status: "🔄 Metadata tersimpan, memproses audio..." — memberi tahu user bahwa proses lanjutan sedang berjalan.

Fase B — Asinkron (Audio Extraction & Transcription)
Vercel memicu GitHub Actions workflow melalui repository_dispatch, mengirim payload berisi URL Reels/TikTok.
GitHub Actions runner menjalankan yt-dlp untuk mengekstrak audio dari link tersebut, dikonversi ke format audio ringan (mis. mp3/ogg) via ffmpeg.
Audio dikirim ke Groq Whisper API untuk mendapatkan transkripsi teks penuh.
Workflow mengirim hasil transkrip kembali ke endpoint Vercel (atau langsung update ke Supabase).
Groq AI menganalisis gabungan dari: OpenGraph Text + Audio Transcript + Note Manual User, menghasilkan DRAFT JSON: Judul Ringkas, Kategori, Tag, Ringkasan Poin, dan Alasan Simpan.
Bot mengedit pesan sebelumnya dengan hasil analisis lengkap dan tombol interaktif konfirmasi.

  Simpan Langsung  
Confirmation Inline Keyboard yang ditampilkan bot: [✅ Simpan Langsung]  [📝 Edit Manual]  [❌ Batal]
Persistence: Setelah user klik ✅ atau memberikan instruksi edit, data resmi tersimpan ke Supabase Database (termasuk kolom audio_transcript yang kini terisi).

Trade-off yang perlu diketahui: total waktu tunggu dari kirim link sampai hasil analisis lengkap kini berkisar 30–90 detik (tergantung cold-start GitHub Actions runner + durasi download/transkripsi), bukan instan seperti asumsi v1.0. UX pesan status bertahap (Fase A → Fase B) dirancang untuk mengelola ekspektasi ini.

3.2. Flow 2: Advance Management via Web Dashboard
Authentication: Protected route sederhana (Single User Auth / Passcode / Supabase Auth).
Interactive Data Table & Gallery View: Menampilkan daftar link tersimpan dalam bentuk kartu referensi atau tabel interaktif.
Full-Text & Semantic Search: Fitur cari kata kunci yang didukung oleh PostgreSQL Full-Text Search atau Supabase Vector Search.
Manual Categorization Management: Fitur untuk membuat, mengedit, menghapus, atau menggabungkan kategori/tag secara fleksibel.
Export Data: Kemampuan mengekspor seluruh data ke file CSV/JSON sewaktu-waktu sebagai backup.
4. DATABASE SCHEMA (SUPABASE POSTGRESQL)
Schema tidak berubah secara struktural dari v1.0 — kolom audio_transcript yang sebelumnya disiapkan sebagai reserved field kini aktif digunakan sejak v1.1.

-- Enable Vector Extension for Semantic Search
CREATE EXTENSION IF NOT EXISTS vector;
 
-- Table: Categories
CREATE TABLE categories (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(50) UNIQUE NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);
 
-- Table: Bookmarks
CREATE TABLE bookmarks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    url TEXT NOT NULL,
    title TEXT NOT NULL,
    summary TEXT,
    user_note TEXT,
    audio_transcript TEXT, -- AKTIF di v1.1 (worker GitHub Actions)
    processing_status VARCHAR(20) DEFAULT 'pending', -- BARU: pending|processing|done|failed
    category_id UUID REFERENCES categories(id) ON DELETE SET NULL,
    tags TEXT[],
    source_platform VARCHAR(30),
    ai_raw_response JSONB,
    embedding VECTOR(1536), -- Perlu dipastikan konsisten dgn model embedding yg dipakai
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);
 
-- Index for Fast Searching
CREATE INDEX idx_bookmarks_url ON bookmarks(url);
CREATE INDEX idx_bookmarks_tags ON bookmarks USING GIN(tags);

Tambahan v1.1: kolom processing_status ditambahkan agar dashboard bisa menampilkan status "sedang diproses" untuk bookmark yang audio-nya belum selesai ditranskripsi oleh worker — penting karena sekarang prosesnya asinkron.
